# M21 content-minimization compatibility facts (no redaction)

This installs a private, account-linked compatibility ledger, immutable digest helper and transactional capture trigger. It changes exactly three existing SQL function bodies: enqueue duplicate detection, private provider binding and signed provider-event correlation. Public RPC signatures, ACLs and return shapes stay unchanged. The cadence begin function, worker, transport, HTTP signature checks, preferences and unsubscribe logic are unchanged. No actual minimizer, cleanup invocation, schedule, provider call or activation is introduced.

Every existing job receives a UTF-8 byte-length-prefixed SHA-256 fingerprint of its original kind/subject/HTML/text. Prepared jobs additionally receive the existing prepared-envelope digest and canonical address hash. No plaintext subject, body, address, unsubscribe link or raw token is duplicated. Backfill aborts on unsupported/mismatched prepared jobs or contradictory existing provider digests. Existing job/provider rows are not edited. Historical envelope time uses the latest known creation/update checkpoint, not an invented delivery timestamp. All minimized markers remain null.

The AFTER INSERT/selected-UPDATE trigger binds content facts before a newly enqueued job transaction can commit and envelope facts inside the existing SENDING/cadence transaction. A failure rolls back the marker, reservation and facts together. No additional application await is inserted before transport. Existing enqueue dedupe still honors the first schedule and never overwrites a conflicting body. Same logical key/body now compares the durable original content digest, which can later survive placeholder content. Different kind/body remains conflict. The theoretical hash-collision boundary is SHA-256, not an absolute equality proof.

No content-edit RPC is added. Privileged edits of an unprepared job keep its content hash synchronized, preserving existing owner-only diagnostic/fixture behavior. Once an envelope is bound, changing content/envelope facts through ordinary job updates is rejected. The ledger and trigger helper have no direct anon/authenticated/service_role privileges; existing owner-definer RPCs invoke them in their normal transactions. No new privilege elevation is introduced. Account/job deletion cascades to facts, consistent with existing private message/provider data; cadence reservations still use their separate no-FK policy.

The private minimized timestamp is only a future compatibility marker, not permission to redact. When marked, the trigger accepts only accepted/suppressed terminal placeholders (`[Content removed]`, `<p>Content removed.</p>`, `Content removed.`) with a null prepared payload and unchanged kind. Current production job CHECK constraints still prohibit null prepared data for accepted jobs, and this migration does not relax those constraints or mark any job. A future owner-only minimizer must first lock the job then its facts, enforce age/holds/evidence/idle-sender requirements, atomically set the marker and approved placeholders, and record an audit. It must never minimize pending/preparing/sending/manual uncertainty.

Provider binding and callback correlation now compare against bound digest/address facts. Existing unprepared/missing jobs remain ignored; provider/digest/recipient conflicts remain rejected; signed/API facts remain independent, out-of-order callbacks stay append-only, and no callback changes queue status or permits resend. A missing prepared payload is accepted for evidence only when the job is accepted and explicitly marked minimized with bound envelope facts. Thus a future accepted tombstone can receive late correlated evidence without keeping bearer links/content; suppressed and unresolved states are not given a new payload-free correlation exception. The provider receipt uniqueness and event conflict rules are unchanged.

Deduplication retains the original job row/key; this patch does not delete jobs or create account-independent content tombstones. Valid unsubscribe tokens stay in their separate account-linked ledger for account lifetime. Facts are linkable pseudonymous metadata, not anonymity, consent or a replacement for provider evidence. Their retention follows the eventual job/minimizer design; the owner can still alter private rows directly, so no tamper-proof-against-owner guarantee is made.

Generated tests cover exact backfill, Unicode/length-prefix dedupe, original-key conflicts, marker/budget rollback on fact failure, signed-before-API/duplicate events, unsafe minimization rejection, late valid and conflicting callbacks after simulated terminal placeholders, account deletion and surviving unsubscribe links. The future placeholder path is simulated only in a rollback-only disposable fixture that temporarily removes the existing CHECK; the production migration does not remove it. Existing cadence, worker, recovery, retention and metadata-cleanup SQL acceptance are rerun on the integrated schema. No real message was redacted or sent. Local/hosted migration and acceptance, publishing and the actual bounded 90-day minimizer remain subsequent gates.
